# 构架与功能开发提示词

版本：0.6 · 2026-10-03  
主责：给外部生成构架与功能开发说明时使用的提示词。不覆盖 `19`、`20`、`21`、`26`、`27`。

```text
请根据《华裳·从蚕到神》（Silk to Divinity，工程代号 HuaShang）的现行手册，以及已经按该手册对齐过的设计说明，写一份「游戏构架设计与整体功能开发」文档。语言正式、简体中文。这份文档告诉程序先写什么、每个功能归哪个模块、怎样算做完。它不是第二套玩法规则，也不是第二套数值表。

【权威】
设计基线是 docs/00 至 docs/29。doc/ 是散稿，不作为实现依据。
模块写入权以 docs/19 为准，仿真边界以 docs/03 为准，数字只在 docs/04，表字段和 ID 以 docs/05 为准，运行时存档以 docs/21 为准，目录以 docs/20 为准，顺序和退出条件以 docs/27 为准，能否给人玩以 docs/26 为准，工具以 docs/29 为准。
与手册冲突时改本文去符合手册。需要数字时只写「见 docs/04 相应小节」，不把区间抄进代码说明，不在类里写死第二套重力、弯曲或风力。

【工程现状，按此继续，不另起工程】
- 仓库根目录已是 Unity 工程，编辑器锁在 6000.6.4f1。渲染管线 URP。已有 Timeline、Input System、uGUI、Test Framework。
- MagicaCloth 2 已导入 Assets/MagicaCloth2。com.unity.modules.cloth 是引擎自带布料模块，不使用它做服装。
- 游戏代码目录 Assets/HuaShang/ 已留出 Scripts、Cloth、Patterns、Characters、Stages、Data，目前没有游戏脚本，也没有可玩闭环。
- 官方示例在 Assets/MagicaCloth2/Example (Can be deleted)，不放进首发场景。
- 角色与衣服从 Blender 以 FBX 进入（应用缩放，向前 −Z、向上 Y，1 单位 = 1 米）。贴图从 Krita 进入，色彩空间见 docs/29。
- 镜头用 Cinemachine，从 Package Manager 添加；首发日常试玩不依赖完整 Xcode。
- 声音用 Unity 自带音频。FMOD、Wwise、Marvelous Designer、CLO、Style3D、Houdini、Substance 首发不装，见 docs/29 §6。
- 不发布 WebGL、主机、移动端、微信小游戏。

【构架约束】
玩法用普通 C# 模块加纯函数。工艺、品质、热度、契合不做成 ECS，也不做成可视化脚本的第二套规则。布料解算只交给 MagicaCloth 2 的 MeshCloth。
配置表做成 ScriptableObject，放在 Assets/HuaShang/Data，字段对应 docs/05。首发关闭的行保留在表里，enabled 为 false，不从工程删除。
只有解算模块可以写 cloth。工艺模块写分数和掩膜。演出写演出记录，历史还原和视觉增强只改拷贝，不改仓库里的染层。展览写展位和当日标记。界面不保存另一份品质分。
cloth 可以不进存档。读档时按 docs/03 的顺序重算。只有 clothLocked 存在时才跳过重算。schema 为 1，不迁移 doc/ 时代的存档。
随机只用 hash(档 id, 日序)，读档不重掷。首发季节恒为 spring，哈希先接在委托上。
工艺在玩家确认时结算。养蚕是唯一的离屏日结：工坊日结束时结算，人不在蚕房也生效。织和染不离屏自动完成。
离开工位即写盘。

【首发必须能跑通的闭环】
新档用开局的绢做成靛蓝襦裙，西施完成 0 档，衣服进柜。同一天里还有一件未完成的东西。
品种只有 suSha、juan、chou、zhuMa。染料只有 indigo、madder、gardenia。形制只有 ruQun，部件是上襦、裙、披帛。
角色只有 xiShi（0 和 30）、wangZhaoJun（0）、zhaoFeiYan（0，3 级才出现）。舞台只有 stage_classic。
实时布料只挂人台、舞台和近处展柜。织机是动画和节拍。染缸特写可以有液面，离开染缸后颜色在材质实例上。

【输出章节】

1. 构架目标
   用一段话说明运行时由哪几块组成，以及首发帧率目标：1080p、布料质量高、演出接近 60 帧；最低档关掉 MagicaCloth，只留蒙皮，允许 30 帧，颜色和透明度仍正确。见 docs/19。

2. 模块与写入权
   列出存档、工艺、解算、演出、展览、界面。每块写：拥有的数据、允许调用谁、禁止写什么。
   明确工艺纯函数与 MagicaCloth 组件的边界：纯函数产出 cloth 描述，解算模块把它写入部件上的 SerializeData，并调用 SetParameterChange()。
   固定项不按品种分：gravityFalloff = 0，triangleBendingConstraint.stiffness = 1，粒子 radius = 0.02。摩擦和按品种的迭代次数没有字段。

3. 数据与存档
   配置表：variety、dye、pattern、character、stage、quest、activity。ID 使用手册拼写，不新造同义 ID。
   运行时物品：yarns、bolts、garments，字段见 docs/21。写明何时写入：下机、出缸、入库、离开工位、工坊日结束、演出结束、每日首次开馆。
   给出「缺 cloth 时重算」和「有 clothLocked 时不覆盖」两条路径，对应测试 S2、S3。

4. 场景装配
   首发不是七张开放地图。用一条工位链（走廊上的门即可）进入：蚕房、织机坊、染坊、裁缝阁、市集、舞台、博物馆。每个地点列出该场景上的组件：哪些是动画，哪些挂 MeshCloth，哪些只读库存。
   舞台场景只放一位高或极致布料的角色。展厅走近 3 米内，当前一件升到高，其余保持中。见 docs/03 §3。
   Timeline 资产放在 Assets/HuaShang/Stages。一条 Timeline 四条轨道：动画、MagicaWindZone、灯、摄像机。0 档没有转身事件就不挂侧风。

5. 布料功能
   按部件挂 MeshCloth，身体用 MagicaCapsuleCollider，风用 MagicaWindZone。
   每个启用品种一个 URP Shader Graph 主材质，实例写底色、染层、色花掩膜、粗糙度、透明度、金线掩膜、结构法线。
   质量档切换只开关组件和解算层，不换一套贴图。
   把 docs/03 §5 的四条视觉证明写成开发任务：素纱透出内层靛蓝、素纱袖与绸袖同风延迟不同、高低画质颜色一致、30 秒 0 档不穿身不炸布。这四条没过之前，不加第四个丝织品种。

6. 功能开发顺序
   严格按 docs/27，不得倒序。每个里程碑写：要做的功能、落在哪个目录、读哪些表、退出条件引用哪条测试。不要写人月。

   P0 表和存档：ScriptableObject 加载；schema 1 读写；N1–N6 用无头测试通过。此时可以没有场景。
   P1 布料探针：灰盒人台或灰盒舞台跑通四条视觉证明。没有 P1，不做 P4 的粒子和 30 档演出。
   P2 工位链：从织到染到裁缝到人台。不看舞台也能分清素纱和绸。覆盖 F2、F3 所依赖的物品规则。
   V 首日：教学三步（docs/10）能在第 1 天走完，对应发布门第 1 条和 F1。
   P3 蚕与委托：春蚕能缫出细丝；3 级前教学不被随机委托打断。委托刷新使用规定的哈希。
   P4 演出与柜子：0 档和西施 30 档可播；F4、F5 通过。关闭的角色不出现在上场门。
   W 首季前的一天：发布门九条里，除「首季见过季节」外，首发范围的条目通过。季节差异记到下一阶段，不在首发里打开夏秋冬。

7. 各功能的完成定义
   用表列出首发功能，而不是愿景功能。列至少包括：开局库存、工时与结束今天、织、染、裁、缝、人台、拆衣、呈现模式、西施 0/30、王昭君与赵飞燕的解锁、0 档演出、展柜、丝钱、过程声。
   每一行写：触发、写入的存档字段、不写入什么、对应的 N/F/S 或发布门编号。
   等级只打开 docs/10 里标记为首发的内容。等级不提高布的风力。好感不提供属性点。

8. 界面、输入与声音
   信息层级遵循 docs/12，不另做一套把精确过程分常驻在主界面上的 HUD。过程分界面默认不展示精确值。
   输入用已安装的 Input System，键鼠。操作声和静音规则见 docs/18：关掉音乐后，织机和缝制仍有操作声；字幕默认开启。
   首发拍照：0 档一条镜头路径；自由相机留到 30 档，限制在舞台盒子内，不能穿进布料。不接社交分享。

9. 明确不做
   列出并写明代码里不要出现的入口：每根经线粒子、整缸持久流体、19 人同时高模布料、70 档完整语音、云锦/缂丝/改机的制作、自由纸样、多人、付费跳过、WebGL、主机认证。
   这些内容若已有表行，保持 enabled: false。不要为它们建场景或做并行系统。

10. 目录、命名与测试布局
    脚本放在 Assets/HuaShang/Scripts，按模块分子目录，名称与 docs/19 的模块对应。
    资源命名遵循 docs/17（如 SK_xiShi、SK_part_skirt、M_cloth_suSha）。
    纯函数测试放在 Unity Test Framework，不依赖场景，先覆盖 N1–N12 和 S1–S3。场景测试只承担 P1 的四条视觉证明和 P4 的演出播放。
    改 docs 后的阅读器由 tools/build_reader.py 生成。本文若引用手册，不手改 HTML。

【写法】
先给模块图（可用文字树或表），再给里程碑。功能表只覆盖首发闭环。
不设计新的品质公式，不重排解锁等级，不把 19 位美人的 70 档拆成首发任务。
类名可以建议，但写入权必须和 docs/19 一致。建议名若与手册 ID 冲突，改类名，不改 ID。
```
